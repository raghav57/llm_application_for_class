## 7.1 – Why Validation Is Needed

A response can be valid JSON but still contain incorrect or incomplete data.

Examples:

- Negative revenue.
- Missing required fields.
- Invalid confidence scores.
- Incorrect data types.

JSON formatting alone does not guarantee that the response satisfies the application's data requirements.

## 7.2 – Pydantic Validation

Use `StockAnalysis.model_validate_json()` to validate the JSON generated by the LLM.

```python
from pydantic import ValidationError

try:
    stock_analysis = StockAnalysis.model_validate_json(stock_json)
    print("Validation successful!")

except ValidationError as error:
    print(error)
```

Pydantic checks the generated data against the defined schema, including field types, required fields and constraints.

## 7.3 – Handling Validation Errors

Extract individual validation errors:

```python
for issue in error.errors():
    field = ".".join(str(part) for part in issue["loc"])
    message = issue["msg"]

    print(f"Field: {field}")
    print(f"Error: {message}")
```

This provides field-level feedback that can be sent back to the LLM.

## 7.4 – Automatic Retry

The Value Investing Copilot implements a single automatic retry.

Workflow:

1. Receive the initial LLM-generated JSON.
2. Validate it using Pydantic.
3. Capture validation errors if validation fails.
4. Send the original JSON and validation feedback to Qwen.
5. Receive corrected JSON.
6. Validate the corrected response again.

The implementation uses:

- `ollama.chat()` for the correction request.
- `StockAnalysis.model_json_schema()` for structured generation.
- `StockAnalysis.model_validate_json()` for revalidation.
- `ValidationError` for capturing validation failures.

Only one retry is attempted. If the second validation fails, the application reports the error.

## Important Learning Distinction

**Structured Output ≠ Valid Data ≠ Factually Correct Data**

- Structured output controls the response format.
- Pydantic validation checks compliance with the defined schema.
- Neither guarantees that the generated financial information or investment recommendation is factually correct.

## Final Learning Outcome

Students build an error-guided correction mechanism that makes LLM applications more reliable by combining structured generation, Pydantic validation and a controlled automatic retry.
